部署与发布

网站与应用自动部署方式全览

从一次 git push 到线上可访问，中间可以完全无人值守。本文按项目形态梳理三条主流路线、常见平台取舍，以及四种发布触发方式。

整理于 2026 年 9 月 · 面向个人项目与小型团队的轻量部署场景

1自动部署到底自动了什么

所谓自动部署，就是把「本地手工做的事情」搬到远端，由平台或 CI 在代码变更时自动执行。核心链路始终是这四步。

STEP 01
代码推送
git push 到远端仓库，或合并 Pull Request 触发钩子
STEP 02
拉取与构建
在干净环境中安装依赖，执行 build 产出静态文件或镜像
STEP 03
发布到运行环境
产物上传到 CDN、对象存储，或重启容器 / 云函数
STEP 04
生效与回滚
切换流量到新版本，失败时一键回退到上一个版本

2三条路线，按项目形态选

最关键的判断只有一个：你的项目有没有服务端。这个答案直接决定能走哪条路。

纯静态前端

静态托管平台

HTML / CSS / JS，或 Vite、Next.js 打包后的产物

  • 代表Vercel、Netlify、GitHub Pages、腾讯 EdgeOne Pages
  • 流程推送即构建，产物自动分发到 CDN 节点
  • 优点零服务器运维，PR 可生成独立预览链接
  • 成本个人用量基本免费
限制：无法运行后端代码、数据库或服务端鉴权，数据只能存在浏览器本地。
带后端服务

云托管与容器平台

需要接口、数据库、用户登录的全栈应用

  • 代表腾讯云 CloudBase、CloudStudio、Railway、Render、Fly.io
  • 流程识别 Dockerfile 或运行时，构建镜像后常驻运行
  • 优点静态资源与后端接口一体化托管
  • 成本有免费额度，正式使用通常按量计费
注意：Railway、Render 等机房在境外，面向国内用户的站点优先考虑 CloudBase 一类国内节点。
完全自控

自建服务器 + CI

已有云服务器，或对数据与环境有强管控要求

  • 代表GitHub Actions + SSH rsync、Docker Compose + Nginx、Jenkins
  • 流程CI 编译产物后推送到服务器，执行重载或重启容器
  • 优点环境、端口、日志、回滚策略全部自己掌握
  • 成本服务器费用 + 自行维护证书与监控
代价：HTTPS 证书续期、日志轮转、故障恢复都要自己承担，适合愿意长期维护的场景。

3常见平台横向对比

同一类别内部差异主要体现在访问速度、免费额度与配置自由度上。

平台 支持后端 国内访问 适合场景
Vercel仅 Serverless一般，偶有波动前端框架项目，追求极致部署体验
Netlify仅 Serverless一般静态站点、表单与函数等轻量需求
GitHub Pages不支持偏慢开源项目主页、文档站，完全免费
EdgeOne Pages不支持快面向国内用户的静态站点
腾讯云 CloudBase支持快全栈小项目，需要数据库与云函数
Railway / Render支持较慢容器化后端，海外用户为主
自建服务器支持取决于机房需要完全掌控环境与数据的项目

4发布的四种触发方式

部署平台解决「怎么发」，触发方式解决「什么时候发」。多数场景用第一种就足够。

代码推送触发

on: push / branches: main

最主流。每次 push 或合并到主分支即自动构建发布，也可只对特定分支生效。

手动点击触发

on: workflow_dispatch

在控制台点一下按钮才发布。适合生产环境，避免误提交直接上线。

定时任务触发

on: schedule / cron

按固定时间自动构建。常用于数据每日更新、定时生成报表的站点。

本地命令推送

vercel --prod / 部署 CLI

不依赖 Git 钩子，本地执行一条命令直接上传产物，适合快速演示与临时预览。

5怎么选：四步判断

按顺序回答这四个问题，答案基本就出来了。

  1. 有没有服务端？纯前端走静态托管；需要接口、数据库、登录就走云托管或自建。
  2. 用户在境内还是境外？境内优先 EdgeOne Pages、CloudBase；境外或自用可选 Vercel、Railway。
  3. 要不要花钱？个人项目优先挑免费额度足够的平台，注意免费方案通常有流量与构建时长上限。
  4. 愿不愿意维护服务器？不愿意就用托管平台，把运维交给平台；愿意则自建，换取完整控制权。
